# 量潮数据运营管理手册

> 本文档整合了量潮数据/量潮科技的客户服务章程、项目交付流程、框架协议、岗位权责、交付标准及定价规则，形成从客户接入到项目交付、从对外合作到内部管理的完整业务体系。

---

# 第一篇 客户服务章程

## 一、总则

### 1.1 目的
为保障客户服务的稳定性、专业性与可预期性，建立统一服务标准与运行机制，避免服务依赖个人状态，确保业务长期健康发展。

### 1.2 适用范围
适用于公司所有客户服务相关业务（含课堂BU、数据BU）及全体成员。

### 1.3 定义
客户服务：指从客户接入到最终交付全过程中的响应、沟通、执行与反馈行为的总和。

## 二、基本原则

1. **结果导向**：以客户实际体验为最终评价标准。
2. **Owner负责**：每个客户必须有唯一负责人，对结果与体验负责到底。
3. **响应优先**：先响应，再解决；不得出现客户被忽视。
4. **标准化**：服务必须可复制、可预期，不依赖个人能力波动。
5. **异常优先**：风险与异常优先级高于常规流程。
6. **复盘闭环**：所有问题必须沉淀为规则或流程优化。

## 三、角色与职责

职责可协同，责任不可转移。

| 角色 | 职责 |
|------|------|
| **COO** | 制定与优化客户服务制度；监督整体执行；主导重大异常与机制调整 |
| **秘书长（中台）** | 日常监控客户状态；协调资源与跨角色问题；跟踪异常处理进度 |
| **Owner（客户负责人）** | 客户第一责任人；负责响应、推进、结果与关系维护；负责闭环 |
| **执行人** | 按标准完成具体交付；对任务质量与进度负责 |

## 四、权责体系

### 4.1 决策权
- **是否接单**：负责人/管理层决策
- **方案调整**：Owner主导，必要时上报
- **异常处理**：Owner先行，重大问题升级

### 4.2 责任机制
- 客户体验问题 → Owner负责
- 执行问题 → 执行人负责
- 系统问题 → COO负责

### 4.3 追责原则
出现以下情况需复盘并明确责任：响应超时、交付延误、客户投诉。不允许模糊归因或集体免责。

## 五、运行机制与流程

### 5.1 客户接入
1. 明确需求
2. 指定Owner
3. 建立沟通渠道

### 5.2 响应机制
- **工作时间**：14-45分钟内响应
- **非工作时间**：2小时内响应
- 响应必须包含"理解 + 下一步动作"

### 5.3 服务流程
- **课堂BU**：建群 → 课前确认 → 上课 → 作业 → 反馈
- **数据BU**：需求 → 执行 → 同步 → 交付 → 确认

## 六、监督与反馈

### 6.1 数据监控
必须记录：响应时效、是否超时、当前节点、客户状态（🟢🟡🔴）。

### 6.2 状态管理
- 🟢 **正常**：按计划推进
- 🟡 **风险**：存在延误可能
- 🔴 **异常**：已发生问题，优先处理

### 6.3 检查机制
- **每日**：检查异常客户
- **每周**：统一复盘（若有）

### 6.4 反馈机制
所有问题必须转化为：流程优化、标准补充、责任明确。

## 七、核心底线
1. 不允许客户被忽视
2. 不允许责任不清
3. 不允许服务不稳定

# 第二篇 项目交付工作流程

## 核心目标

确立PM为项目总负责人，对"项目成功"负总责，并协调各方资源实现目标。

**项目成功公式：** 项目成功 = 客户满意（PM负责）× 商业可行（商务）× 交付优质（技术）× 财务健康（财务）

## 第一阶段：项目启动与规划

### 一、前期客户需求沟通与分析

- **负责部门**：技术部
- **工作文档**：客户需求问卷 / 客户需求管理
- **工作内容**：
  1. 技术部门邀请客户填写需求表，根据需求与客户进行深入沟通，全面了解项目目标、具体要求、数据规模、时间节点等信息。
  2. 务必争取客户提供样例数据（Demo）。技术基于Demo编写数据清洗等核心流程的伪代码，并与客户确认。
  3. 当信息足够全面时，PM应同步协调技术人员开始撰写初步的《项目策划书/方案》。
- **PM职责**：确保沟通会议发生，督促文档产出，开始形成项目初步范围认知。

### 二、技术团队评估可行性

- **负责部门**：技术部执行，PM跟进
- **工作内容**：技术部评估技术实现难度、所需技术资源、预计工作周期、预计所需人力等。

**棘手问题处理原则（PM需知悉并支持）：**
1. **能力范围内**：正常推进。
2. **模糊不确定**：向客户说明"问题可解，但方案需细化"，按正常流程推进内部研究。
3. **重大困难，暂无想法**：仍先承诺客户"可解"，同时立即以内部咨询请求形式上报，获取高层或专家方案后，交由一线技术执行。（核心：对外保持信心，对内快速升级）

### 三、任务分配与资源规划策略

- **合同启动时间策略**：默认实施起始时间为合同签订后1个月或下个月初。通过定价和激励政策（如加急费）来筛选和应对客户紧急程度，压缩项目运作时间。
- **核心-实训生任务分层策略**：
  - 合同签订后，PM牵头技术组进行整体任务拆分。
  - 将非核心、模块化、验收标准明确的任务（如数据整理、基础模块开发、重复测试等）剥离出来。
  - **Plan A（主方案）**：将上述任务打包，优先安排给课程BU的实训生执行，用于锻炼和筛选人才。
  - **Plan B（兜底预案）**：必须设置预案（如额外缓冲时间、核心成员可随时接手），确保实训生若未完成，绝不影响主项目进度。
- **前提条件**：该策略要求有足够客户来源，因此新媒体运营和客户推荐需配套有效启动。同时内部管理可靠性要求高，既要管理好项目周期，也要管理好供给侧。

## 第二阶段：项目交付与服务执行

### 四、外部客户沟通标准流程（PM全权负责）

- **唯一接口**：PM代表团队与客户进行所有正式沟通。
- **响应黄金步骤**：
  1. **即时响应**：首先回复"收到，正在组织内部评估/讨论，将尽快给您答复"。
  2. **问题定位**：分析问题性质（需求、Bug、咨询、变更等）。
  3. **任务分发**：将定位后的任务分配给明确的责任人（技术、商务、财务等），并限定明确Deadline。同步在飞书任务中创建事项。
  4. **汇总回复**：收集各责任人答复后，整合成完整、专业的回复，统一向客户反馈。
  5. **循环往复**：客户再次提问，重复步骤1-4。
- **PM核心能力评价标准**：能否独立组织完成以上循环，无需频繁找上级协调或审核。

### 五、服务过程中的需求变更管理

- 使用飞书审批功能中的"项目立项、报价申请、预算、合同申请"提交相应的审批。
- 所有变更必须通过商务协同区的"需求变更追踪"流程进行评审（涉及技术评估、商务报价、合同修订）。
- **PM职责**：作为变更控制经理，发起并跟进变更流程，确保任何变更都经过评估、批准并记录在案。

### 六、项目监控与汇报

- 每一个工作节点由PM负责工作汇报，至少每3天主动向客户更新一次进度，并同步内部核心团队。保持信息透明，管理预期。

## 第三阶段：协同支撑区（PM的作战仪表盘）

PM应主动利用并维护以下协同区，以驱动项目成功公式的四个维度：

| 协同区 | 用途 | 关键看板 |
|--------|------|----------|
| **商务协同区** | 管理商业可行性与合同健康度 | 需求变更追踪、报价审批状态、合同条款管理 |
| **财务协同区** | 确保项目财务健康 | 成本控制仪表、利润实时计算、回款进度看板 |
| **课程BU协同区** | 高效利用实训生资源，支持交付 | 实训生技能矩阵、任务匹配看板、成长反馈记录 |
| **PM-客户协同区** | 主动管理客户满意度与价值交付 | 客户满意度指数、需求优先级矩阵、价值交付追踪 |

## 第一条 定义

- **框架协议/本协议**：指双方签订的《数据处理服务框架协议》正文及其全部附件、补充协议及修订文件。
- **工作订单**：指依据本协议，由双方不时签署的就具体服务项目、服务范围、交付物、服务期限、费用等进行约定的书面文件。每一份有效签署的《工作订单》均为本协议不可分割的组成部分。
- **服务**：指乙方根据本协议及相关《工作订单》的约定，向甲方提供的数据处理及相关服务，包括但不限于数据采集、清洗、脱敏、标注、转换、分析、挖掘、存储及数据管理服务等。
- **数据**：指甲方提供或为履行本协议之目的在服务过程中产生、收集、处理的所有数据。
- **个人信息**：指以电子或者其他方式记录的与已识别或者可识别的自然人有关的各种信息，不包括匿名化处理后的信息。
- **知识产权**：包括但不限于著作权、专利权、商标权、商业秘密、专有技术、数据库权利等。

## 第二条 框架协议与工作订单

本协议作为双方开展数据处理服务合作的总括性约定。除双方另有明确书面约定外，所有具体服务项目均应通过签署《工作订单》确认。

每一份《工作订单》应至少包含：服务内容与范围、技术指标与交付标准、服务起止时间或里程碑计划、费用与结算方式、验收标准等。若《工作订单》条款与本协议冲突，应以《工作订单》的明确书面约定为准，但涉及保密、数据安全、知识产权归属及违约责任基本原则的条款除外。

## 第三条 服务内容与方式

**服务范围**包括但不限于：
- 数据采集与汇聚
- 数据清洗、去重、格式转换
- 数据脱敏、匿名化处理
- 数据标注、分类、标签化
- 数据分析、建模、可视化
- 数据安全存储与托管
- 其他双方书面确认的数据处理服务

**交付物**：除非《工作订单》另有约定，乙方应在服务完成时向甲方交付约定的全部数据处理结果、分析报告、源代码（如适用）和相关文档。

## 第四条 双方的基本权利与义务

**甲方权利与义务：**
- 有权要求乙方按照约定标准交付数据服务成果，并对服务过程进行监督和阶段性评审。
- 应按约定向乙方提供必要的数据源、资料、接口权限及工作配合。
- 应按约定向乙方支付服务费用。
- 未经乙方书面同意，不得对乙方提供的带有知识产权的技术工具等进行反向工程或向第三方透露。

**乙方权利与义务：**
- 有权依据《工作订单》的约定收取服务费用。
- 应按约定的质量、进度和标准完成数据处理服务。
- 应使用合法、正版且安全的工具软件和硬件设备提供服务。
- 除为履行本协议之目的外，不得对甲方数据进行任何与本协议无关的使用、复制、传播或转让。

## 第五条 数据处理与个人信息保护

**双方数据处理角色**：甲方为个人信息处理者，乙方为甲方的受托处理者。

**乙方处理规则：**
- 乙方仅可基于本协议确立的目的、方式和范围处理甲方数据。
- 未经甲方事先书面同意，乙方不得将委托处理的个人信息转委托任何第三方处理。
- 服务期限届满或协议终止后，乙方应在甲方要求的时间内将数据返还或彻底删除。

**安全措施**：乙方应采取加密传输与存储、访问权限控制、日志审计、脱敏处理等措施，确保数据处理过程中的保密性、完整性、可用性和可恢复性。

**应急处置**：发生数据泄露等安全事件时，乙方应立即通知甲方并提供事件详情及应对措施。

## 第六条 服务费用与支付

具体服务项目的费用、计价方式及支付条件，由双方在相应《工作订单》中约定。所有价款均为含税价，乙方应在甲方付款前开具等额、合法的增值税专用发票。

## 第七条 知识产权

- **甲方数据与成果归属**：甲方原始数据始终属于甲方。服务过程中产生的交付物、结构化数据、分析模型等知识产权归甲方所有。
- **乙方预置工具**：乙方在服务开始前即拥有的软件、算法框架等知识产权仍归乙方所有。

## 第八条 保密义务

双方对于因签署及履行本协议而知悉的对方商业秘密、技术秘密等负有严格保密义务。保密义务在本协议终止后持续有效，直至保密信息进入公有领域为止。

## 第九条 违约责任

- 乙方逾期完成服务，每逾期一日支付对应金额万分之五的违约金。
- 乙方违反数据安全保障义务，应支付违约金并承担全部实际损失。
- 甲方逾期支付费用，每逾期一日按应付未付金额的万分之五支付违约金。

## 第十条 不可抗力

因不可抗力导致一方不能履行本协议的，该方不承担违约责任，但应及时书面通知对方。

## 第十一条 协议期限与终止

# 第四篇 内部岗位权责章程

**依据文件：** 《数据处理服务框架协议》

## 一、总则

为明确框架协议下本公司（作为服务方/乙方）各岗位在数据处理服务中的职责边界、协作关系与权限划分，保障服务质量、数据安全与合规性，提升项目管理效率，特制定本章程。

## 二、岗位设置与职责

依据框架协议要求，设立以下核心岗位（可一人兼任，但数据安全与合规专员不得同时担任存在利益冲突的终审环节）：

### 1. 项目经理（PM）

**职责：**
1. 作为甲方指定联系人的唯一或主接口人，统筹《工作订单》的协商、签署、变更与关闭。
2. 组织内部资源，制定服务实施计划、里程碑与交付时间表。
3. 监控服务进度与质量，定期向甲方通报进展。
4. 管理项目费用结算流程，确认工作量、账单与发票出具。
5. 发生数据安全事件或违约风险时，立即启动内部上报并协调对外通知。

**权限：**
- 调动项目所需人员与技术资源。
- 审批内部服务交付物初稿，代表公司在《工作订单》范围内签署日常通讯文件。
- 暂停不符合质量或安全要求的内部作业，要求返工。

### 2. 数据技术负责人 / 数据工程师

**职责：**
1. 根据《工作订单》完成数据采集、清洗、脱敏、标注、分析、建模、可视化等服务。
2. 严格遵守甲方提供的数据源使用限制，只在授权目的下处理数据。
3. 使用正版、安全的技术工具与环境。
4. 区分并标记甲方原始数据、处理结果数据及公司预置工具，防止知识产权混淆。
5. 在交付物中提供完整的技术文档与代码说明。

**权限：**
- 使用公司授权范围内的软件、算法库及计算资源。
- 申请获取为履行服务必要的甲方接口权限和数据样本。
- 要求项目经理或安全专员提供合规指引。

### 3. 数据安全与合规专员（DPO/安全官）

**职责：**
1. 制定并维护数据处理安全保障措施（加密、脱敏、访问控制、日志审计、备份恢复等）。
2. 审核每个《工作订单》中涉及个人信息的数据处理活动。
3. 管理转委托第三方事宜，监督第三方签署不低于协议水准的书面合同。
4. 组织数据安全事件应急响应。
5. 协调内部资源配合甲方审计。
6. 服务结束时监督执行数据返还或彻底删除。

**权限：**
- 对内部所有涉及数据处理的操作有独立检查、监督权，可直接向高层管理汇报。
- 在存在数据安全隐患时，有权要求立即暂停相关数据处理活动。
- 审核和批准数据处理相关工具、平台的引入。

### 4. 质量审核员（QA）

**职责：**
1. 对数据处理结果、报告、代码、文档等进行独立核查。
2. 记录并反馈质量问题，跟踪缺陷修复状态。
3. 参与服务成果的签字确认环节。

**权限：**
- 驳回不符合质量要求的交付物，要求工程师返工。
- 调阅数据处理的中间过程记录、日志及测试结果。

### 5. 商务 / 法务对接人

**职责：**
1. 审核《工作订单》中费用、计价方式、违约金、知识产权归属等商务条款。
2. 确认公司预置工具的知识产权清晰。
3. 处理与框架协议相关的争议、索赔、变更协议等。
4. 就保密义务向项目团队进行提示。

**权限：**
- 审核对外签署的订单及补充协议，确保不超越框架协议基本盘。
- 就违约风险发出预警，代表公司进行协商谈判。

## 三、协作与沟通机制

- **内部沟通**：每周召开项目例会，PM、技术负责人、QA、安全专员必须参加。
- **变更评估**：凡涉及甲方数据范围变更、工具引入或跨团队转委托，必须经安全专员及商务/法务对接人双线评估并形成书面记录。
- **对外接口**：所有与甲方的正式承诺、验收确认、问题回复，统由项目经理归口发出，其他岗位不得擅自对外作出承诺或解释。

## 四、违规与问责

任何岗位人员违反本章程，导致框架协议履行瑕疵、数据安全事故或知识产权纠纷的，公司将按内部管理制度进行问责，包括但不限于通报批评、扣减绩效、解除劳动合同等。

# 第五篇 交付标准

## 一、交付清单

- **数据工程**：数据集、数据工程文档、（可选）数据处理器（GitHub上命名规范，方便后续代码复用和思路查找）
- **项目管理**：项目管理文档
- **商务管理**：报价单、合同等

## 二、交付流程

| 阶段 | 交付内容 |
|------|----------|
| **设计阶段** | 数据工程文档、项目管理文档、报价单、合同等 |
| **实施阶段** | 根据需要交付更新 |
| **交付阶段** | 数据集、数据工程文档 |

## 三、交付规范

根据客户需求，将交付数据打包成一个压缩包，通过邮箱发送进行交付。

## 四、交付相关约定

1. 最后数据交付时，先发实例给客户确认。
2. 客户支付尾款后再交付全部数据，并且由技术组通过邮件正式交付。
3. 告知客户3天内未反馈问题即为交付成功。

# 第六篇 定价与商务规则

## 一、定价总则

每个项目需要盈利20-30%。

## 二、服务类型及基础定价

提供爬虫、智能标注、数据处理等，按难易程度分类：

| 难度等级 | 定价 |
|----------|------|
| 简单 | 3,000元 |
| 中等 | 6,000元 |
| 困难 | 10,000元以上 |

## 三、数据标注特殊定价

根据准确度不同定价不同，起步价不同：

| 准确度 | 起步价 | 备注 |
|--------|--------|------|
| 60% | 6,000元以上 | |
| 70% | 8,000元以上 | |
| 80% | 12,000元以上 | 需人工标注 |
| 90% | 18,000元以上 | 需人工标注 |

## 四、加急项目加价

基于正常工作周期，按缩短时间比例加价：

- 缩短一周内：加价20-50%
- 缩短2-4周：加价50-150%

## 五、不同数量级溢价

| 数据量级 | 溢价幅度 |
|----------|----------|
| 百万以下 | 基础定价 |
| 百万到千万 | 基础定价上溢价30-50% |
| 千万到亿 | 基础定价上溢价60-100% |
| 亿以上 | 基础定价上溢价100%以上（根据实际情况） |

## 六、其他费用

1. **云服务费**：数据量大的项目需要上云，收取客户云服务费，费用根据数据估计量提前收取。
2. **API调用费**：数据标注若需要大模型API调用，收取相应费用。
3. **会议咨询费/答疑费**：根据困难程度，300-600元/小时。

## 七、报价单组成及比例

报价单包括设计、实施、交付三个环节，正常比例是 **3：4：3**。若某一环节工作量加大，可拉高该环节的占比。

需求变更、项目周期变更、价格变更需要与客户补签协议。
