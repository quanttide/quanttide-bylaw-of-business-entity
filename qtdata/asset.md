# 量潮数据资产管理章程

## 一、总则

### 1.1 目的

为规范量潮数据业务线的资产分类、存储、版本管理与交付流程，确保资产可追溯、可复用、安全可控，制定本章程。

### 1.2 适用范围

本章程适用于量潮数据业务线所有项目产生的数字资产，包括数据资产、文档资产和代码资产。

### 1.3 定义

- **数据资产**：项目过程中涉及或产生的数据集，包括原始数据、清洗后数据、分析结果数据
- **文档资产**：项目管理文档、数据工程文档、商务文档等
- **代码资产**：数据处理脚本、notebook、工具代码等
- **交付物**：按客户需求打包的最终交付成果

## 二、资产分类

### 2.1 数据工程

- 数据集：原始数据、中间数据、最终数据
- 数据工程文档：数据模型定义、处理流程说明、字段字典
- 数据处理器：Python脚本、notebook（GitHub 上命名规范，方便后续代码复用和思路查找）

### 2.2 项目管理

- 项目策划书
- 需求规格说明书
- 进度报告
- 变更记录
- 验收报告
- 项目复盘报告

### 2.3 商务管理

- 报价单
- 合同及补充协议
- 发票与付款记录
- 客户沟通记录

## 三、版本管理

### 3.1 数据集版本

同一项目可能交付多个版本，须在交付物名称或元数据中标注版本号，支持追溯。

### 3.2 文档版本

所有项目文档须标注版本号和修改日期。重大修改须在文档中记录变更说明。

### 3.3 代码版本

代码资产统一托管至 GitHub 仓库，遵循语义化版本规范，commit message 须清晰描述变更内容。

## 四、存储与归档

### 4.1 存储规范

- 代码资产：托管至 GitHub 仓库，按项目建立独立仓库或目录
- 文档资产：存放至公司知识库，按项目归类
- 数据资产：按项目归档至指定存储路径

### 4.2 归档要求

项目结束后，项目经理须在[7]个工作日内完成全部资产归档：

- 整理项目文档、沟通记录、代码资产
- 确认数据集完整可读
- 归档至公司知识库，方便后续类似项目复用

### 4.3 保留期限

客户交付物的保留期限以合同约定为准。超期后原始数据将自动清理，届时重新获取可能产生额外工作量费用。

## 五、交付流程

### 5.1 交付物打包

根据客户需求，将交付数据打包成一个压缩包，通过邮件等正式渠道发送。文件命名须包含项目名称与版本号。

### 5.2 内部审核

交付前须经项目经理内部审核，确认交付物完整、数据集无误、文档齐全。

### 5.3 客户确认

交付后启动反馈期。客户在约定时间内确认收到并验收。超期未反馈视为通过。

## 六、安全与合规

### 6.1 访问控制

资产须按角色设置访问权限。未经授权不得复制、传播客户数据。

### 6.2 数据保护

- 客户数据须加密传输
- 涉及个人信息的数据须脱敏处理
- 不得在非授权环境中存储客户数据

### 6.3 删除与返还

服务结束后，根据客户要求返还或彻底删除客户数据（含备份），并出具删除完成证明。

## 七、附则

### 7.1 生效与修订

本章程自发布之日起生效。当业务需求变化时，由数据BU办公室负责修订。
