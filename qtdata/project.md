# 量潮数据评估与设计阶段工作流程

## v1

### 前期客户需求分析
- **负责部门**：技术部
- **工作文档**：客户需求问卷
- **工作内容**：
  - 技术部门先邀请客户填写需求表，根据需求与客户进行深入沟通，全面了解客户需求，包括项目目标、具体要求、数据规模、时间节点等信息。
  - 同时要求顾客那边给demo，在有demo的情况下，技术人员可以开始对清洗过程做伪代码编写，并将伪代码流程和顾客确定好。
  - 在沟通的过程中，如果客户给的信息够全面，可同步联系技术人员撰写策划书。

### 技术团队评估可行性
- **负责部门**：技术部
- **工作内容**：技术部门对项目的可行性进行评估，包括技术实现难度、所需技术资源、预计工作周期、预计所需人力等。
- **p.s. 如果遇到棘手问题**：
  - 不管客户那边给什么样的问题，我们现在都确定我们这边可以给解决方案，如果
    1. 处于我们一线技术人员能力范围内，就正常走。
    2. 如果模糊不确定，说明大概可以解决，也跟正常范围走。
    3. 如果大家都觉得很困难，初期没什么想法，也接下来，但是以咨询的形式上报，上报之后得到解决方案再交给一线技术解决。

### 服务过程
- 服务过程中需求变更
  - 使用飞书审批功能中的"项目立项、报价申请、预算、合同申请”提交相应的审批
- 每一个工作节点由PM负责工作汇报、每3天推动一次。

### 任务分配
1. 合同的默认实施时间从1个月以后开始，或者下个月月初开始。我们通过定价要求客户披露自己的紧急程度。可以通过接受我们的其他激励政策和加钱来让我们提前开始实施，减少项目的运作时间。
2. 合同签后，PM牵头技术组做整体任务拆分，将其中非核心、模块化、有明确验收标准的任务（如数据整理、基础代码模块开发、测试用例执行等）安排给实训生执行。目的是释放项目组核心成员精力，聚焦于关键架构与其他核心业务。
   - Plan A：将这些任务打包，优先安排给实训生完成，用于锻炼和筛选人才。
   - Plan B：设置兜底预案（如额外资源/缓冲时间），实训生若未完成，核心组能立刻接手，不影响主项目。
3. 这个策略的前提是我们要能够有更多的客户，所以新媒体运营和客户推荐需要配套有效启动。对于内部管理的可靠性要求也很高，一方面要能够管理好项目周期，另一方面也要能够管理好供给侧。

## v2

### 以PM为核心的项目交付与协同操作指南

**核心目标**：确立PM为项目总负责人，对“项目成功”负总责，并协调各方资源实现目标。  
**项目成功公式**：项目成功 = 客户满意（PM负责）× 商业可行（商务）× 交付优质（技术）× 财务健康（财务）  
**全局工作流与PM职责总览**：PM需全程主导并串联以下阶段，确保信息畅通、决策高效、风险可控。

### 第一阶段：项目启动与规划

#### 1. 前期客户需求沟通与分析（PM组织，技术主导）
- **工作文档**：客户需求管理
- **工作内容**：
  - 技术主导沟通：技术部门邀请客户填写需求问卷，并主导沟通，全面了解项目目标、具体要求、数据规模、时间节点等。
  - 获取Demo与确认流程：务必争取客户提供样例数据（Demo）。技术基于Demo编写数据清洗等核心流程的伪代码，并与客户确认。
  - PM同步启动：当信息足够全面时，PM应同步协调技术人员开始撰写初步的《项目策划书/方案》。
- **PM职责**：确保沟通会议发生，督促文档产出，开始形成项目初步范围认知。

#### 2. 技术团队评估可行性（技术部执行，PM跟进）
- **工作内容**：技术部评估技术实现难度、所需资源、工作周期、人力预估等。
- **棘手问题处理原则（PM需知悉并支持）**：
  1. 能力范围内：正常推进。
  2. 模糊不确定：向客户说明“问题可解，但方案需细化”，按正常流程推进内部研究。
  3. 重大困难，暂无想法：仍先承诺客户“可解”，同时立即以内部咨询请求形式上报，获取高层或专家方案后，交由一线技术执行。（核心：对外保持信心，对内快速升级）
- **PM职责**：跟进评估进度，明确技术风险和资源需求，为商务报价和计划制定提供输入。

#### 3. 任务分配与资源规划策略（PM主导）
- **合同启动时间策略**：
  - 默认实施起始时间为合同签订后1个月或下个月初。
  - 通过定价和激励政策（如加急费）来筛选和应对客户紧急程度，压缩项目运作时间。
- **核心-实训生任务分层策略**：
  - 合同签订后，PM牵头技术组进行整体任务拆分。
  - 将非核心、模块化、验收标准明确的任务（如数据整理、基础模块开发、重复测试等）剥离出来。
  - Plan A（主方案）：将上述任务打包，优先安排给课程BU的实训生执行，用于锻炼和筛选人才。
  - Plan B（兜底预案）：必须设置预案（如额外缓冲时间、核心成员可随时接手），确保实训生若未完成，绝不影响主项目进度。
- **PM职责**：制定包含缓冲和兜底方案的项目计划，并与课程BU协调实训生资源。

### 第二阶段：项目交付与服务执行

#### 4. 外部客户沟通标准流程（PM全权负责）
- **唯一接口**：PM代表团队与客户进行所有正式沟通。
- **响应黄金步骤**：
  1. 即时响应：首先回复“收到，正在组织内部评估/讨论，将尽快给您答复”。
  2. 问题定位：分析问题性质（需求、Bug、咨询、变更等）。
  3. 任务分发：将定位后的任务分配给明确的责任人（技术、商务、财务等），并限定明确Deadline。同步在飞书任务中创建事项。（找不到人？飞书→微信，必须确保下达）
  4. 汇总回复：收集各责任人答复后，整合成完整、专业的回复，统一向客户反馈。
  5. 循环往复：客户再次提问，重复步骤1-4。
- **PM核心能力评价标准**：能否独立组织完成以上循环，无需频繁找上级协调或审核。

#### 5. 服务过程中的需求变更管理
- **流程遵循**：所有变更必须通过商务协同区的“需求变更追踪”流程进行评审（涉及技术评估、商务报价、合同修订）。
- **PM职责**：作为变更控制经理，发起并跟进变更流程，确保任何变更都经过评估、批准并记录在案。

#### 6. 项目监控与汇报
- PM负责：在每个关键工作节点完成后，向客户及内部进行工作汇报。
- **汇报节奏**：至少每3天主动向客户更新一次进度，并同步内部核心团队。保持信息透明，管理预期。

---

### 第三阶段：协同支撑区（PM的作战仪表盘）

PM应主动利用并维护以下协同区，以驱动项目成功公式的四个维度：

- **商务协同区**
  - 用途：管理商业可行性与合同健康度。
  - 关键看板：需求变更追踪、报价审批状态、合同条款管理。
- **财务协同区**
  - 用途：确保项目财务健康。
  - 关键看板：成本控制仪表、利润实时计算、回款进度看板。
- **课程BU协同区**
  - 用途：高效利用实训生资源，支持交付。
  - 关键看板：实训生技能矩阵、任务匹配看板、成长反馈记录。
- **PM-客户协同区**
  - 用途：主动管理客户满意度与价值交付。
  - 关键看板：客户满意度指数（定期调研）、需求优先级矩阵、价值交付追踪（证明项目成果）。

---

**最终要义**：本指南将PM置于驱动位置，通过标准化流程和清晰的协同界面，赋能PM全面负责项目交付，最终实现客户满意、商业成功、交付优质、财务健康的复合型项目成功。
